The plan

A spec, a harness, and a CLI that never touches jcode

The spec

Planner and worker. Six prompt segments, the first three byte-stable so the prefix cache hits. Typed facts the model proposes and rules commit. Every step a (model, speculation, sampling) triple; nothing defaults.

QGI-2

Eleven crates beside jcode, zero jcode edits. Engine trait for vLLM and SGLang, HiCache and GDN-pool sizing, two edges, a scripted engine that makes the loop testable: 402 tests. Datalog went in, then out: 15 rules, one recursive.

Quark

jcode, branded and wired for the app factory: a stdlib CLI with its own home and hub profile, a runner that speaks AG-UI, a 9K-token prompt instead of 33K, and one prompt policy that is opt-in only.

The heroes of this story, as billed: Enhanced QGI DS V4.1-Flash local and QGI Enhanced Qwen Flash-Next.

Act II · the harness

We built a planner. jcode beat it by 28 seconds.

Same model, same tasks, jcode direct versus jcode through QGI-2.

  • Pass 1: 1/4. Every failure ours: invented tool names, a JSON body where a stream was due, one session shared by everyone.
  • Pass 2: 6/8 at 33.8 s. Plan → tool-args → extract is three engine calls a round where jcode spends one.
  • Pass 3: stop planning, only remember. 8/8, 5.4 s, +4 % tokens.

The matrix · 8 models × 6 arms

Prompt diets help some. The memory tax hits others.

What we keep

Remember more, plan less, host your own

  • The memory layer stays. Free on the models that matter, decisive on long sessions.
  • The step-split planner goes. Native tool calling wins.
  • Self-hosting wins on speed: 14.8 s against 24.3 for the best frontier model and 50+ for the gateway.
  • Effort is a lever, not a virtue. Max and high bought minutes, not answers.
  • Prompt policy is per model. So safe-efficient ships opt-in.
  • Quark ships: CLI and runner in the app factory, 47/47 tests.
