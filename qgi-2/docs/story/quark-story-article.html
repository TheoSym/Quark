A field report from the QGI-2 and Quark trials · 11–17 September 2026

Four Days on Rented Silicon

We rented a supercomputer that couldn't count to three, built a planner that lost to the thing it was planning for, taught a proxy to remember a Wi-Fi password from 88 turns ago, graded sixteen models on a test they nearly all aced, and ran a credit card down to $1.85. Here is everything we measured, and what it means.

Chapter 1 · the premise

A spec, a harness, and a rule: don't touch jcode

The spec asked for something specific. Two models, a planner and a worker. A prompt cut into six segments, the first three byte-stable so the engine's prefix cache actually hits. Typed facts that the model may only propose, with rules deciding what gets committed. And every single step declared as a triple of model, speculation and sampling, because "nothing defaults".

QGI-2 is what came out: eleven crates sitting beside jcode with zero edits to jcode itself, an engine trait that speaks vLLM and SGLang, HiCache tiers and a calculator for the recurrent-state pool that hybrid models quietly need, two edges (an HTTP sidecar and an in-process provider), and a scripted engine that makes the whole agent loop testable without a GPU. The test count ended at 402. A Datalog engine went in and came back out after an audit found fifteen rules of which exactly one was recursive; a worklist does that job in ten lines.

Then there is Quark: jcode, branded and wired for the app factory. A stdlib Python CLI with its own home directory and hub profile, a runner that translates jcode's event stream into the app's AG-UI, a prompt that weighs 9K tokens instead of 33K because nothing from a personal config leaks in, and exactly one prompt policy on board, which stays off unless you ask for it. 47 of 47 runner tests pass.

Chapter 2 · infrastructure

The box that couldn't count to three

The first rental was eight RTX PRO 6000 cards. CUDA initialised happily on any one GPU. On any two. On any three, it failed, every time, with a UVM error that turned out to be a known host driver bug needing a kernel module reload nobody renting the machine can perform. SM120 also wanted FLASHINFER_CUDA_ARCH_LIST=12.0a or FlashInfer's probe tripped the same bug. The box was later destroyed outright by a failed VM conversion, which at least settled the question.

Its replacement was four B200s at 183 GB each, $28 an hour whether serving or idle. The 510 GB planner checkpoint arrived at 5 GB/s. First launch took 35 minutes of kernel JIT and autotune; later launches, five. The obvious layout, tensor-parallel across all four cards, was mostly empty space: a 39-million-token KV pool nobody needed and 556 GB of host RAM pinned for a cache tier that could never get a hit. Two cards at a 0.92 memory fraction with the pool capped at four million tokens served the same model with DSpark accepting 2.9 tokens a step. Three cards is not an option: the vocabulary is 129,280 entries and that does not divide by three.

Chapter 4 · the harness

We built a planner. jcode beat it by 28 seconds.

The honest test of a harness is an A/B against the thing it wraps: same model, same tasks, stock jcode talking straight to the engine versus stock jcode routed through QGI-2. The first pass went 4/4 against 1/4, and every one of the harness's failures was ours. The edge answered a streaming request with a JSON body, so jcode saw silence. The planner was never told the real tool names and invented fs.read. Every run shared one session, so one task's calc.py facts leaked into the next. And stored tool output was sentence-split, so the edit after a read could never match bytes and the planner re-read the same file five rounds running.

Seven fixes later, pass two was the honest one: 6/8 at 33.8 seconds against 8/8 at 5.8. Plan, then tool arguments, then extraction is three engine calls a round where jcode spends one, and a planner separated from its tools is a worse tool user than a model calling them natively.

The harness's value was never speed. It was memory.

So pass three threw the planner out. jcode stays native for everything; QGI-2 becomes a pass-through proxy that records the transcript into a line store, retrieves what matters, and inserts a single <memory> message before the latest user turn, frozen for the turn so the cached prefix stays byte-identical. 8/8, 5.4 seconds, four percent more tokens. Pass four added the spaCy ingester and per-turn compaction and paid one second for them.

Chapter 5 · memory

Eighty-eight turns later, it still knows the Wi-Fi password

Coding tasks never stress memory; they finish long before any budget is hit. So the memory test is a hundred-turn conversation at a fictional robotics startup: twenty facts planted early (the gripper's torque rating, the test floor's SSID, the finance lead's name), filler in between, twenty probes late. Real clients truncate history, so the model only sees the last twelve turns.

With the whole transcript in context, both local models recall 20 of 20, at 169K and 217K prompt tokens. With the window alone: zero of twenty. With the window plus the proxy: 20/20 on Enhanced QGI DS V4.1-Flash local and 18/20 on QGI Enhanced Qwen Flash-Next, at 75K and 85K tokens, which is 44 % and 39 % of the whole-transcript bill, and faster per turn because the prompts are shorter. That morning's first version had scored 13 and 10; the ingester and the compactor closed the gap, and no model changed.

Chapter 6 · office hours

Seven documents, fifty-eight checks, and one model that only talks about files

Agents that can code are common; agents that can produce a correct invoice PDF are rarer. The document bench asks for a Word report, an HTML data report, a memo exported to PDF, a flyer with logo and deck, a PDF invoice, a six-slide deck and an Excel model. Verifiers open the files and check them. A task passes only if every check passes.

Enhanced QGI DS V4.1-Flash local went 7 for 7, 58 of 58 checks, in 9.6 minutes. Gemini 3.8 Flash matched it in 12.3. The gateway's own DeepSeek V4 Pro also got there, in 74 minutes with six gateway errors. DiffusionGemma cheerfully described the file it was about to create and mostly did not create it. The memory proxy cost roughly one task per model here: retrieved lines occasionally steered a run toward an earlier task's file. That is the price, on short sessions, of chapter five.

Chapter 7 · the gate

Everyone gets an A. Speed does the grading.

All of that became one command. The gate runs four legs against one model in ten to twenty minutes: an engine probe, three Exercism exercises, two document tasks plus a two-turn task whose second turn depends on the first, and eight facts recalled from a 40-turn context. Fifteen objective verdicts, nothing judged by another model.

Sixteen models took it. Fourteen scored 15/15. Claude Opus 5 at max effort dropped two, both recall questions answered with an empty string and finish_reason: content_filter. The :batch variant of Fable turned out to be batch-API-only and returned fifty 404s in eleven seconds. QGI-Flash 3.8 Next answered nothing in six ten-minute tasks; the endpoint was simply down. With capability a tie, the clock decides: the two locals at 14.8 and 17.0 seconds, Fable at low effort at 24.3, then a pack of gateway models between 50 and 77, then the reasoners, and finally the gateway's DeepSeek pinned against the ten-minute cap, passing its tests and then refusing to stop.

Chapter 8 · the matrix

Prompt diets help some. The memory tax hits others.

Eight models, six arms, three exercises, forty-eight cells. Four arms change only the prompt jcode runs under: baseline, a safe-efficient coding policy, a search-first "exa-reuse" policy, and the same with the Exa search server actually connected. Two arms put the QGI-2 memory proxy in the path, alone and together with the Exa arm. The two local rows are the 13 September runs, carried over unchanged.

Every cell solved 3 of 3. The arms move seconds and tokens and nothing else, and their sign depends on the model. The safe-efficient diet speeds up Gemini (44 → 34 s), Opus, GLM and both locals, and slows Fable and QGI 3.8 Flash. The memory proxy is free on Fable, where it is the fastest arm of six, a gift to QGI-V4 Pro, neutral on Opus, and a tax on Gemini and above all GLM 5.3, where it costs 4.8×. On Gemini the combination of memory and tool schema drops the cache ratio from 90 % to 59 %: the first measured case of QGI-2's own additions defeating its cache discipline.

And Exa? jcode connected the search server with two tools on all 48 tool-arm runs. No model called it once. On the 13th the local models did, eight times in 56 runs. The tool arms measure the price of offering search, not of using it.

Chapter 9 · the bill

What the agent reports and what the card is charged

What jcode reports is input, output and cache-read tokens. What it does not report is reasoning tokens, and reasoning is what a high-effort model spends most on. So the priced cost of the six frontier gates, computed honestly from the rate card and jcode's counts, came to $5.83. The card was charged $46.99. GPT-6 Astra shows 40 to 61 output tokens per exercise and takes three minutes over each one; the difference is thinking you pay for and never see counted.

Halfway through the matrix every call began failing with HTTP 402: the account could "only afford 62,583" tokens, with $1.85 left of 335. The surprise was the blast radius. The gateway routes Gemini, QGI-V4 Pro, QGI 3.8 Flash and GLM 5.3 through the very same OpenRouter account, so the "gateway" sweep that afternoon had been drawing it down all along: $63.87 on the 14th. After a top-up the 48-cell matrix cost $58.92. Two days, $122.79. Mercury 2.5's entire 15-verdict gate, for scale: one cent.

Chapter 11 · what we keep

Remember more, plan less, host your own

The memory layer stays. Zero to twenty on the long-horizon test, parity on coding, free on the models that matter. Tune it for the models it taxes: GLM 5.3 and Gemini first.

The step-split planner goes. Three engine calls a round lost to one, and a planner without its tools invents them.

Self-hosting wins on speed. 14.8 seconds against 24.3 for the best frontier model and 50 and up through the gateway, with document work at parity with Gemini.

Effort is a lever, not a virtue. Max and high effort bought minutes, not answers, on tasks this size.

Prompt policy is per model. Which is why safe-efficient ships in Quark as an opt-in mode and not a default.

Count the money at the card, not the counter. The gate now records the key's spend delta, because reasoning tokens hide from the agent.

Quark ships. CLI and runner in the app factory, its own home, a 9K-token prompt, 47 of 47 tests.
